# 设计说明

## 业务目标与数据口径

从商家视角评估五个销售渠道的历史净贡献，选择满足门槛的前二名。淘宝/拼多多/抖音按商家实收记录；京东自营供货按商家供货结算额记录，因此不将零售 GMV 与供货收入混用。模拟费率仅用于本任务，各类平台真实税费、结算差异不在范围内。任务不预测边际广告回报。

任务文本 `task_prompt(seed)`、工具定义 `harness.TOOLS` 是智能体可见的初始信息。订单、账务和政策通过业务 API 取得。全部规则可发现，不使用未告知智能体的秘密评分条件。

## 三项挑战如何落实

1. **跨 API 关联与二次计算**：先得到渠道 ID，再取订单 ID，以订单 ID 关联退款/成本，并以渠道 ID 关联费率。按渠道汇总后计算净收入、渠道费、贡献、退款率、资格和排序。没有 API 返回最终分析结果。订单、退款、成本三类数据各自不可替代，正常从未知数据计算至少需要三类独立调用；标准路径实际为五类业务 API、八次调用。
2. **合理干扰**：GMV 排行榜看似可直接推荐渠道，但含未支付交易且未扣退款成本；ROAS 为广告归因口径；库存与本任务无关。订单含 device/campaign，账务含 reason/kind，渠道含 owner 等非必要字段。工具描述不掩盖口径差异，智能体仍需自主选择接口和字段。
3. **隐含查询约束**：订单属于 6 月，不等于账务只查 6 月。必须取目标订单 ID 后查询截至 7 月 15 日的账务；5 月订单的 6/7 月退款不能混入。账务 API 同时返回 pending/draft，需从政策推导状态筛选。完全退款不删除原订单，退款不直接冲回成本。资格门槛先于排名应用，退款率精确交叉相乘，不先四舍五入百分比。

“至少三次调用”是接口的信息依赖属性，**不做调用次数奖励或强制轨迹检查**。任何公开、确定性数据集都可能被记忆或猜中；训练时应在可信 Harness 内保存环境状态，并划分不重叠 seed。公开源码任务不能在拥有本地执行权限的模型沙箱中声称防止作弊。

## 典型执行路径

| 步骤 | 调用 | 参数与数据依赖 | 输出及后续用途 |
|---|---|---|---|
| 1 | list_channels | region=east，由“华东”映射得到 | 5 个渠道 ID |
| 2 | get_channel_policy | 无；可与步骤 1 换序 | 费率、3 单/20%/正贡献门槛、确认规则 |
| 3–6 | list_orders | 5 个渠道 ID，2026-06-01 至 2026-07-01，paid，按 next_cursor 继续 | 共 18 个原始已支付订单 |
| 7 | list_refunds | 步骤 3–6 的订单 ID；as_of=2026-07-15 | 退款事件，过滤 confirmed 后按 order_id 汇总 |
| 8 | list_fulfillment_costs | 同批订单 ID 与截止日 | 过滤 booked，保留成本贷项的负号 |
| 本地计算 | 无业务 API | 关联订单、费率和两种账务汇总 | 5 行指标、资格、前二排名及合计 |

退款和成本可交换调用顺序。每批最多 20 个 ID，扩容时需分批。退款/成本均先分别聚合到订单粒度再关联，避免一单多退款、多成本造成笛卡尔乘积放大。

## 数据与边界

内置 6 个渠道（含不属于华东的干扰渠道）、36 条订单记录；其中目标订单 18 条。数据覆盖跨期退款、一单多退款、全额退款、待确认退款、晚于截止日的退款、运费、负成本贷项、草稿成本、截止日后的成本、取消订单及月份边界外订单。seed 改变金额，订单 ID 也带 seed。

seed=0 的审核结果：

| 渠道 | 订单数 | 实收分 | 退款分 | 净收入分 | 成本分 | 渠道费分 | 净贡献分 | 合格 |
|---|---:|---:|---:|---:|---:|---:|---:|---|
| 淘宝 C01 | 4 | 87149 | 5070 | 82079 | 39133 | 2462 | 40484 | 是 |
| 京东 C02 | 4 | 60171 | 3681 | 56490 | 33369 | 3954 | 19167 | 是 |
| 拼多多 C03 | 4 | 81032 | 18264 | 62768 | 29387 | 2825 | 30556 | 否，退款率 |
| 抖音店播 C04 | 4 | 30155 | 1765 | 28390 | 30076 | 710 | -2396 | 否，负贡献 |
| 抖音达人 C05 | 2 | 44166 | 4214 | 39952 | 20938 | 2397 | 16617 | 否，订单数 |

例如拼多多净贡献高于京东，但退款率超过 20%，不能入选。这使“先排净贡献，再忽略门槛”的策略产生实质错误。

## 验证与奖励

验证入口只接收 `(自然语言任务, 最终结果)`。任务解析为已注册的版本和 seed，重建可信 SQLite 数据，通过独立 SQL CTE 聚合参考答案。样例智能体使用 Python 循环与 Decimal；验证器使用 SQL 聚合与整数舍入，避免直接复用样例答案计算过程。二者共享数据和配置，因为它们描述同一个环境。

奖励为 40% 数值字段精确正确率、20% 资格正确率、20% 推荐集合正确、10% 排名正确、10% 推荐集合及合计正确。数值正确率分母为固定 35，资格分母为固定 5。遗漏不改变分母；渠道行顺序不影响分数，排名顺序影响分数。空推荐只在参考结果本身为空时算推荐正确。

JSON 结构非法得零分；合法但不完整结果按字段得分。未知任务得零分并附独立错误代码，Harness 应将 UNKNOWN_TASK 视为配置问题而非有效训练样本。验证器内部不可恢复的系统故障应由 Harness 标记为基础设施失败，不能伪装成模型零奖励。评分细项适合离线诊断，训练时可以只消费 float reward，不向智能体提供参考答案。

## 工程边界与适用训练

标准库实现，无大模型接口、第三方数据服务或 HTTP 服务。内存 SQLite 生命周期与 episode 一致，不生成代理可读取的数据库文件。`Episode.step` 是工具路由白名单，`Episode.grade` 仅供训练端使用；同一进程的 Python 对象隐藏不能替代操作系统隔离。

适合训练 API 参数选择、分页收集、关系关联、时间/状态约束推理、精确算术、带门槛的排序以及 JSON 输出。当前 seed 变化主要影响金额，业务结构相对固定；应保持训练/测试 seed 分离，防止把模板记忆误认为泛化。规则扩展、不同业务结构或新的金额分布需要新任务版本。这里交付单场景引擎，不批量生成模型轨迹，不声称完成实际 RL 训练或已测得大模型成功率。
